# S9 词汇生产 AI 成本估算表设计说明

## 设计目标

为 S9 词汇生产系统提供**可预测、可验证、可追踪**的 AI 调用成本模型。决策者拿到这张表后能回答三个问题：

1. **一个词多少钱？** → 预算估算 Sheet 三档场景给出每词均价
2. **实际花了多少？** → 生产记录 Sheet 自动计算每批实际成本
3. **预算准不准？** → 汇总分析 Sheet 预算 vs 实际偏差一目了然

---

## 整体结构：四 Sheet 闭环

表格按**参数驱动 → 预算推导 → 实际记录 → 偏差分析**的闭环组织：

```
┌─ Sheet 1：参数配置 ─────────────────────────────────────┐
│  唯一的输入源：总词数、模型定价、Token预估、调整因子         │
│  修改此处，所有计算自动联动                                 │
└──────────────┬──────────────────────────────────────────┘
               ▼
┌─ Sheet 2：预算估算 ─────────────────────────────────────┐
│  三档场景（乐观/中等/悲观）的成本推导                       │
│  + 极端场景（全部走满3轮重生成）                            │
│  公式全部引用 Sheet 1 参数，零手工输入                      │
└──────────────┬──────────────────────────────────────────┘
               ▼（生产开始后）
┌─ Sheet 3：生产记录 ─────────────────────────────────────┐
│  每批填入实际 Token 消耗，成本列自动计算                     │
│  50 行批次槽位，汇总行自动求和                              │
└──────────────┬──────────────────────────────────────────┘
               ▼
┌─ Sheet 4：汇总分析 ─────────────────────────────────────┐
│  预算 vs 实际对比 + 按模型成本构成 + 批次均价趋势           │
│  全部自动引用 Sheet 2/3 数据                               │
└─────────────────────────────────────────────────────────┘
```

---

## 各 Sheet 设计逻辑

### Sheet 1：参数配置

**作用**：全表唯一的输入源，所有其他 Sheet 的公式都引用此处，做到"改一处、全联动"。

包含四个区域：

#### 1.1 核心输入（B3:D4）

| 设计决策 | 说明 |
|---------|------|
| 总词数（C4） | 唯一需要手工修改的数字，当前为 500 |
| 提示文字 | D4 标注"← 修改此处，所有计算自动更新"，引导使用者 |

#### 1.2 模型定价（B6:F9）

| 设计决策 | 说明 |
|---------|------|
| 只列两个模型 | Gemini-3-Flash-Preview 和 GPT-5.2——系统实际只用这两个 |
| 标注 model_id | 对应 51talk AI Gateway 后台（64 / 78），方便核价 |
| 分 INPUT / OUTPUT | 两种模型的 Input/Output 单价差异大（GPT 输出价是 Gemini 的 ~4.7 倍），分开才能看出成本结构 |
| 单位统一 | ¥/百万 token，与 AI Gateway 计费口径一致 |

#### 1.3 生成维度 Token 预估（B11:H20）

7 个生成维度逐行列出，每行包含：

- **模型**：6 个 Gemini + 1 个 GPT（例句）
- **调用粒度**：syllable 按单词、其余 6 个按义项——这个区别直接影响多义词的调用次数乘数
- **Input / Output Tokens**：基于实际 Prompt 文件字节数推算，G 列标注原始字节数可追溯
- **汇总行**：7 次 AI 调用/词，总计 Input 10520 + Output 1800 tokens

#### 1.4 质检 Layer 2 Token 预估（B22:G31）

7 个 QC L2 维度，全部用 Gemini，结构与生成维度平行。底部注释：Layer 1 是 22 条纯算法规则，零 AI 成本。

#### 1.5 调整因子（B33:G39）

5 个因子，每个给出**乐观/中等/悲观**三档值：

| 因子 | 为什么需要 | 三档范围 |
|------|-----------|---------|
| 平均义项数 | 多义词使按义项维度的调用成倍增加，这是最大变量 | 1.0 / 1.3 / 1.8 |
| 助记有效率 | valid=false 的助记跳过 QC L2，节省 AI 调用 | 0.6 / 0.75 / 0.9 |
| L1 通过率 | Layer 1 拦截后不进 L2，节省 AI 调用 | 0.9 / 0.95 / 0.98 |
| 审核重生成率 | reject 触发重新生成（最多 3 次） | 0.02 / 0.05 / 0.10 |
| API 重试率 | 网络/限流导致的额外调用 | 0.01 / 0.03 / 0.05 |

### Sheet 2：预算估算

**作用**：将 Sheet 1 的参数组合为三档场景的预算数字，公式全自动、零手工输入。

#### 结构

三个场景区块（乐观 / 中等推荐 / 悲观），每个区块 4 行：

| 行 | 内容 | 公式逻辑 |
|----|------|---------|
| 生成 Gemini（6维度） | syllable 按词 + 其余 5 维度按义项 | `总词数 × (950 + (630+2330+1830+1750+1910) × 义项数)` |
| 生成 GPT-5.2（例句） | 按义项调用 | `总词数 × 1120 × 义项数` |
| 质检 L2（全 Gemini） | syllable 按词 + 非助记 2 维度按义项 + 助记 4 维度按义项×有效率，整体乘 L1 通过率 | 复合公式，体现助记有效率和 L1 过滤 |
| 重试+重生成 | 前三行合计 × (重生成率 + 重试率) | `SUM(前三行) × (重生成率 + 重试率)` |

每个区块底部有**合计**和**每词均价**。

#### 极端场景（B31:I33）

悲观基础成本 × 4 轮（初始 + 最多 3 次重生成），给出最差情况下的成本上限。

#### 关键公式设计

- 三个场景的公式结构完全相同，只是引用调整因子的列不同（D 列乐观 / E 列中等 / F 列悲观）
- 总词数 C2 通过 `='参数配置'!C4` 引用，显示在表头便于确认
- 成本计算：`Token 数 × 单价(¥/百万token) / 1,000,000`

### Sheet 3：生产记录

**作用**：每批生产完成后记录实际 Token 消耗，成本列自动计算。是预算验证的数据来源。

#### 数据来源

系统已支持自动导出生产记录，无需手工填写：

- **API 端点**：`GET /api/stats/production-records` — 返回按 Package 聚合的 JSON 数据
- **xlsx 导出**：`GET /api/stats/production-records/export` — 下载填好数据的 xlsx（admin 权限）

数据链路：`AiUsageLog.package_id → Package`，生成阶段和 QC Layer2 阶段的 AI 调用均自动记录 `package_id`，按模型名（gemini/gpt）分类聚合为 Input/Output Tokens。

#### 结构

| 列 | 内容 | 类型 |
|----|------|------|
| B-C | 批次号、批次名称 | 自动（从 Package 表导出） |
| D | 词数 | 自动（Package.total_words） |
| E-F | 开始/结束时间 | 自动（Package.started_at / completed_at） |
| G-H | Gemini Input/Output Tokens | 自动（AiUsageLog 按模型聚合） |
| I-J | GPT Input/Output Tokens | 自动（AiUsageLog 按模型聚合） |
| K | Gemini 成本(¥) | 公式：`(G×Gemini_Input单价 + H×Gemini_Output单价) / 1M` |
| L | GPT 成本(¥) | 公式：`(I×GPT_Input单价 + J×GPT_Output单价) / 1M` |
| M | 总成本(¥) | 公式：`K + L` |
| N | 备注 | 手工填写 |

#### 设计要点

- **50 行批次槽位**：预留足够空间，无需扩展表格
- **空行保护**：成本列用 `IF(OR(G<>"",H<>""), 计算, "")` 公式，空行不显示零值
- **价格引用统一**：所有成本公式引用 Sheet 1 的模型定价，价格变了自动联动
- **汇总行**（B54）：自动求和所有批次的词数和成本
- **每词均价**（B55）：`总成本 / 总词数`，空数据时不显示

---

### Sheet 4：汇总分析

**作用**：自动聚合 Sheet 2（预算）和 Sheet 3（实际）的数据，提供决策视图。

包含四个区域：

#### 4.1 关键指标（B3:D7）

- 计划总词数（引用参数配置）
- 已完成词数（引用生产记录汇总）
- 完成进度（自动计算百分比）

#### 4.2 预算 vs 实际对比（B9:F12）

| 指标 | 预算（中等） | 实际 | 偏差 | 偏差率 |
|------|------------|------|------|--------|
| 总成本 | 引用预算估算 | 引用生产记录 | 自动 | 自动 |
| 每词均价 | 自动 | 自动 | 自动 | 自动 |

#### 4.3 实际成本构成（B14:E17）

按模型维度拆分：Gemini 和 GPT-5.2 各占多少、比例多少。

#### 4.4 批次成本明细（B19:F40）

逐批显示词数、总成本、每词均价，以及**累计均价**趋势——可以看到随着生产推进，实际成本是趋于稳定还是在漂移。累计均价公式为 `SUM(前N批总成本) / SUM(前N批词数)`。

## 关键设计决策

### 为什么用"四 Sheet"而非一张大表

- **关注点分离**：参数输入、预算推导、实际记录、分析视图各司其职
- **权限可控**：可以只给运营人员编辑"生产记录"Sheet 的权限
- **引用清晰**：所有公式的数据流向是单向的（参数配置 → 预算估算 / 生产记录 → 汇总分析）

### 为什么用"三档场景"而非"单一估计 + 误差范围"

- 三档（乐观/中等/悲观）比置信区间更直觉，非技术决策者也能理解
- 每档的因子值可独立调整，支持 what-if 分析
- 中等场景标注"推荐参考"，给出明确的预算锚点

### 为什么把 Gemini 和 GPT 分开统计

- 单价差 3-5 倍，混合统计会掩盖成本结构
- 分开后能直接看到"如果例句改用 Gemini 能省多少"
- 与代码中 `_DIMENSION_MODEL_MAP` 的模型映射一一对应

### 为什么生产记录用 Token 而非金额输入

- Token 是系统原始输出，无需人工换算，减少录入错误
- 模型价格调整后，历史记录的成本自动重算（因为公式引用的是 Sheet 1 的当前价格）
- 分 Gemini/GPT 的 Input/Output 四列，与系统 AI 用量追踪 API 的输出口径一致

## 如何使用这张表

| 场景 | 操作 |
|------|------|
| 调整生产规模 | 改 Sheet 1 的 C4（总词数），所有预算自动更新 |
| 模型价格变了 | 改 Sheet 1 的定价区域（B8:D9），预算和历史成本自动重算 |
| 每批生产完成 | 访问 `GET /api/stats/production-records/export` 下载最新数据，或直接看 JSON API |
| 预算审批 | 看 Sheet 2 的三档场景，推荐参考"中等"那组 |
| 成本复盘 | 看 Sheet 4 的预算 vs 实际偏差，以及累计均价趋势 |
| 词表特征变了 | 调 Sheet 1 的调整因子（如平均义项数从 1.3 改为 1.5） |
