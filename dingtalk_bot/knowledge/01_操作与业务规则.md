# S9 词汇生产质检系统 — 操作手册（审核员/管理员）

系统目标：把人教版中小学英语教材词表整合为标准词库，为每个词的每个义项生成
音标/音节、释义、语块、例句、助记五维内容。最终用户是中小学生。**fail-safe：未审核通过的内容不进最终产出。**

## 角色与登录

- **角色**：`admin`（管理员）/ `reviewer`（审核员）。邮箱验证码首次登录自动注册为 reviewer；admin 只能由 CLI `vocab create-admin` 创建。
- **登录**：发验证码 → 输入验证码（写 httpOnly Cookie，4 小时过期）。邮箱须在域名白名单内。
- **限流**：默认每用户 600/分钟（按 user_id 计，同一出口多人不互相挤）。

## 一、词表导入

- **预览**（不入库）：上传文件返回前 5 条 + 总条数。
- **导入**：解析入库并创建一个生产批次（Package）。
- 支持格式：`.xlsx / .xls / .csv / .json`（带 magic-bytes 校验）。
- 批次名默认取文件名；同名且非 pending 批次默认拒绝（409），加 `force=true` 才清理旧 pending 数据重导（不删已生成的非空内容、不删跨包共享数据）。
- **< 1000 词同步**返回；**≥ 1000 词后台异步**，立即返回 batch_id。
- 导入只产出 meaning（释义）/ phonetic（音标）；五维内容由后续"生产"生成。
- 文件大小上限由配置控制（默认 10MB，超限 413）。
- 权限：admin + reviewer 都可导入。

## 二、生产 / 重新生产

对批次跑流水线：**生成内容 → Layer1 算法质检 → Layer2 AI 质检 → 失败项进审核队列 → 通过项自动 approved**。

**模式区别**：

| 模式 | 怎么触发 | 命中范围 | 是否覆盖已有 | 角色 |
|---|---|---|---|---|
| 全量补生产 | 生产（不指定维度） | 仅 PENDING 项 | 否 | admin+reviewer |
| 维度子集重生（默认） | 指定 `dimensions=[...]` | 指定维度，但跳过"指纹=最新 prompt 版本"的项 | 是 | **仅 admin** |
| 强制重生 | 上面 + `force_overwrite_recent=true` | 指定维度全部项，忽略指纹 | 是（全覆盖） | 仅 admin |
| 仅补缺字段 | 上面 + `only_missing_extra_field=true` | 只补"content 非空但缺主 extra 键"的项 | 否 | 仅 admin |

- 合法可重生维度：`chunk`、`sentence`、`syllable`、`mnemonic_root_affix`、`mnemonic_word_in_word`、`mnemonic_sound_meaning`、`mnemonic_exam_app`。
- **重生前建议先用预览**：返回 `would_reset`（真正会动的数量）、`skipped_recently`（因已是最新版被跳过）等，前端"勾维度→显示将影响 X 条"二次确认，预览不改数据。
- 状态门禁：importing→409；processing→409（超时会强制重置）；failed→重置僵尸项回 pending 支持断点续跑。
- 生产期间 Package 为 `processing`，其关联词不会被审核批次领取（防并发冲突）。
- 连续 3 个子批失败会终止整个生产，失败项进审核队列、不牵连好内容。

## 三、一键补全缺失字段（全库回填，仅 admin）

扫描**所有**词包中"content 非空但缺 `extension_words`（词根词缀）/ `exam_sentence`（考试应用）"的项，逐包后台补生成。服务端编排、跨包去重、幂等（重复触发只补还缺的）、关浏览器不影响。
- 预览返回 `total_missing`（各包累加，跨包共享会重复计）与 `unique_missing`（去重后真实缺失数）。
- 仅针对 `mnemonic_root_affix`、`mnemonic_exam_app` 两个有 extra 字段的维度。
- 用途：回填"改了生成器代码后残留的缺字段旧数据"。

## 四、人工审核

审核员领一批待审词，逐项处理。最多重新生成 **3 次**。

- **领批**：默认 10 个词/批（1–50），按词分组（一个词的所有待审项打包同批）；已有未完成批次则返回该批。
- 可：跳过某词（释放回池）、释放整批、查进度统计。
- **逐项操作**：
  - **通过(approve)**：内容 approved。
  - **重新生成(regenerate)**：原子计数+上限检查。达上限且**内容为空**→自动 reject 留空；达上限且**有内容**→提示"请手动修改"；生成器判该助记类型不适用→直接 rejected。重生后自动跑质检，过则 approved。
  - **人工修改(edit)**：**只跑 Layer1、跳过 Layer2 AI**；拒绝 HTML 输入（防 XSS）。
  - **标记不适用**：仅助记维度；清空+rejected+记录 prompt 指纹（prompt 升级后才会重做）。
  - 批量重新生成：异步，返回 run_id 轮询进度。
- 并发保护：审核项已分配他人时操作报 409。
- 死锁自愈：领批时自动清理"无 UI 出口"的孤儿项（rejected / 空内容且重试耗尽），落终态，防批次卡死。

## 五、导出（门禁见业务规则）

- **Excel**（admin+reviewer）：含"审核人"列（按义项聚合审核人，`; ` 拼接）+ "审核时间"列。
- **JSON 流式下载 / 单词导出 / 就绪度**：仅 admin。就绪度返回 total/approved/pending/ready_rate。
- 被 reject 的维度在导出里**留空属正常**。

## 六、总表（MasterTable）

按词浏览全部数据，可不走领批流程直接改（适合 rejected 等非队列项）：
- 列表支持搜索 + 按状态过滤（approved / in_progress）。
- 直接重生 ContentItem（仅 admin，跑完整 QC 含 L2）。
- 手动编辑（admin+reviewer，只跑 L1；`force_approve=true` 可人工判定正确直接 approved）。
- 标记不适用（仅助记维度且仅当前 approved 的项）。
- 总表的"维度子集重生""一键补全"实际调用第二、三节的批次接口。

## 七、Prompt 管理（仅 admin）

三级 fallback：DB → 文件（docs/prompts/generation/）→ 硬编码。可增删改查、归档/复原、文件→DB 同步（含 dry-run 预览）、seed 默认。
- 改 prompt 后，已有内容因双指纹匹配在重生时可能被跳过——需用强制重生或维度子集重生回灌。

## 八、用户管理（仅 admin）

创建/列表/编辑用户（改 name/role/is_active）。**禁止 admin 改自己的角色、禁止停用自己**（防系统锁死）。
